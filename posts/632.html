Docker常用命令速查：5条必会操作

2026-09-23 · 工具

在团队协作中，工具的正确配置往往能带来指数级的效率提升。本文整理了经过线上验证的最佳实践，帮助你少走弯路。

核心要点

本文将从以下 5 个方面展开，带你系统掌握相关知识：

  1. 全局忽略文件：避免临时文件污染仓库
  2. 别名配置：让长命令一键触发
  3. 变基整理：让提交历史清晰可读
  4. 贮藏功能：临时切换上下文不丢工作
  5. 钩子机制：在提交前自动检查代码

1. 全局忽略文件：避免临时文件污染仓库

每个开发者的本地环境不同，会产生各种临时文件。全局gitignore让你不用在每个仓库都重复配置。

git config --global core.excludesfile ~/.gitignore_global

# .gitignore_global
.DS_Store
*.swp
*.swo
.idea/
.vscode/
*.local

2. 别名配置：让长命令一键触发

通过别名机制，将常用的长命令简化为几个字符。不仅节省输入时间，还能减少拼写错误。

alias gs='git status'
alias gc='git commit -m'
alias gp='git push origin HEAD'
alias gl='git log --oneline --graph -20'

3. 变基整理：让提交历史清晰可读

交互式变基可以合并提交、调整顺序、修改提交信息，让分支历史像精心编排的故事线。

git rebase -i HEAD~5

# 常用指令:
# p = pick (保留)
# s = squash (合并到上一个)
# r = reword (修改信息)
# f = fixup (丢弃信息)

4. 贮藏功能：临时切换上下文不丢工作

正在写一半代码突然要切分支修bug？stash可以暂存当前修改，处理完再恢复，不用提交半成品。

git stash push -m "wip: 半完成的功能"
git checkout hotfix-branch
# ... 修bug ...
git checkout feature-branch
git stash pop

5. 钩子机制：在提交前自动检查代码

pre-commit钩子可以在每次提交前自动运行代码检查、格式化、测试，确保提交的代码符合规范。

# .git/hooks/pre-commit
#!/bin/sh
echo "Running code lint..."
py lint src/ || exit 1
echo "Running tests..."
pytest -q || exit 1

为了方便你快速对比和记忆，这里整理了一个汇总表格：

配置项 作用 推荐设置
user.name / user.email 提交者身份 真实姓名和公司邮箱

最佳实践

  • 优化的同时保持代码可读性，不要为了性能牺牲可维护性
  • 关注瓶颈，优化最慢的那一环，而不是平均用力
  • 建立性能基准，每次优化后对比结果
  • 考虑边际收益，花1天提升10%不如花1天提升2倍

总结

以上技巧都来自真实项目的实践总结，建议你从最简单的一条开始尝试，逐步应用到自己的工作中。工具和方法是死的，人是活的，关键是理解背后的原理并灵活运用。
