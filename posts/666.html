1. 并行处理充分利用多核

CPU密集型任务用多进程，IO密集型任务用多线程或asyncio。选对并发模型，性能轻松翻倍。

from concurrent.futures import ProcessPoolExecutor

def process_item(item):
    # CPU密集型计算
    return sum(i * i for i in range(item))

items = [100_000] * 8

# 串行
results = [process_item(x) for x in items]

# 并行（自动使用所有核心）
with ProcessPoolExecutor() as executor:
    results = list(executor.map(process_item, items))

2. 缓存重复计算的结果

对于调用频繁、参数有限、结果确定的函数，加上缓存装饰器可以避免重复计算，提升一个数量级。

from functools import lru_cache

@lru_cache(maxsize=1024)
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

# 第一次调用慢，后续调用几乎瞬时
print(fibonacci(100))

3. 使用内置数据结构替代自定义对象

很多场景下，tuple、namedtuple、dataclass 比手写的类更轻量、更快。选择合适的数据结构是优化的第一步。

from collections import namedtuple
from dataclasses import dataclass

# 好：轻量且不可变
Point = namedtuple('Point', ['x', 'y'])
p = Point(1, 2)

# 更好：支持类型提示和默认值
@dataclass
class Point:
    x: float
    y: float
    label: str = 'origin'

4. 用局部变量加速属性查找

Python的属性查找是有开销的。在循环内部，将频繁访问的属性或全局函数绑定到局部变量，可以显著提速。

import math

def compute_slow(values):
    result = []
    for v in values:
        result.append(math.sqrt(v) + math.sin(v))
    return result

def compute_fast(values):
    sqrt = math.sqrt
    sin = math.sin
    append = result = []
    append = result.append
    for v in values:
        append(sqrt(v) + sin(v))
    return result

5. 生成器表达式节省内存

列表推导会一次性生成所有元素占用内存，生成器表达式则是惰性计算，逐个产出，处理大数据时差异巨大。

# 坏：一次性加载全部到内存
total = sum([x * x for x in range(10_000_000)])

# 好：逐个计算，内存几乎为0
total = sum(x * x for x in range(10_000_000))

优化手段 适用场景 性能提升 复杂度

多进程并行 CPU密集型任务 2~8倍（看核数） 中

最佳实践

  • 先测量再优化，用数据说话，不要凭感觉
  • 关注瓶颈，优化最慢的那一环，而不是平均用力
  • 考虑边际收益，花1天提升10%不如花1天提升2倍
  • 优化的同时保持代码可读性，不要为了性能牺牲可维护性
